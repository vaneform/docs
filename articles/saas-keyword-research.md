# SaaS keyword research

Originally published at <https://vaneform.com/guides/saas-keyword-research> on 2026-10-04 by Kai · 中文版: <https://vaneform.com/zh/guides/saas-keyword-research>

## Summary

A SaaS keyword plan should tell a team what to publish and how each page relates to the product. This guide works backward from a task the product completes, using a small-team recurring-meetings product as the example, and gives each page a different job, for instance a template page for getting the agenda and a feature page for evaluating the workflow.

It shows how one feature name turns into several customer questions, how to collect wording from the task itself, and how integration queries differ. Competitor data from Vaneform's Site keywords view is used to find language and missing tasks, and a short list is validated in keyword research. The guide includes a brief you can hand to a writer, a way to prioritize the resource you can make useful now, and a post-publication review that compares real Search Console queries against the job you assigned the page. The point is that every keyword ends with a page decision and a single owner page per task.

## Key points and data

- Example page map: /templates/weekly-meeting-agenda (get the asset) vs /features/recurring-meetings (evaluate the workflow).
- Write one sentence of intended value for each candidate page.
- Use competitor ranking terms with their receiving URLs to find language and gaps.
- Keep one owner page per core task.
- Keep the original brief with the published page and review actual queries.
